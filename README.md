## 怎麼「執行」

這是純靜態網站，不需要安裝任何軟體、也不用下指令執行。檔案上傳到 GitHub 並開啟 Pages 後，GitHub 會在 1–2 分鐘內自動發布；之後每次上傳新檔案（Commit）也會自動更新。平常改文字、圖片只要到後台按「檢查並發布」。

4. 到 GitHub repository 打開 `assets/js/config.js` → 鉛筆圖示編輯，找到最後一行 `window.MC_RECAPTCHA_SITE_KEY = '';`，把金鑰貼進引號裡，例如 `window.MC_RECAPTCHA_SITE_KEY = '6Lxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx';` → Commit。
5. 等 Actions 綠勾 → 打開網站按 ⌘+Shift+R → 捲到「線上提問」，表單下方會出現「本表單受 reCAPTCHA 保護…」字樣，代表已啟用。填一則測試提問送出，應能正常送出。

## HTTPS／SSL/TLS 加密防護（v34）

網站全程以 HTTPS（TLS 加密）傳輸。憑證由 GitHub Pages 自動向 Let's Encrypt 申請並自動續約，不需要購買或手動更新。

程式端（v34 已內建，不用設定）：
- 有人用 `http://myopiacare.site` 或 `http://www.myopiacare.site` 開啟時，網頁一載入就改走 `https://myopiacare.site`（GitHub「Enforce HTTPS」之外的第二道保險；本機預覽不受影響）。v38 起 `https://www.myopiacare.site` 也會轉到主網址。
- 內容裡寫成 `http://myopiacare.site/...` 的本站連結自動改成 `https://`；圖片網址寫成 `http://` 時改走 `https://`（安全設定本來就不載入未加密圖片）。後台發布時，按鈕與社群網址的 `http://` 也會自動補正為 `https://`。
- 每個頁面都有內容安全政策（CSP）：程式、字型、圖片、連線只允許 `https://` 或本站；所有頁面（含 404）都設定 `strict-origin-when-cross-origin` 參照政策，不會把網址細節傳給 http 網站。
- 資料庫（Firebase Firestore）、登入、reCAPTCHA、Google 字型全部走 HTTPS。

GitHub 與 GoDaddy 端（照部署指南文件「v34」那一段逐步設定）：
1. GitHub → 網站 repository → Settings → Pages：Custom domain 是 `myopiacare.site`、DNS check successful，勾選 **Enforce HTTPS**。
2. GoDaddy DNS 檢查：`@` 的 A 紀錄只有 GitHub 的 4 個 IP（185.199.108.153／109.153／110.153／111.153）；`www` 是 CNAME 指向「你的 GitHub 帳號.github.io」。**MX 與其他郵件紀錄完全不動。**
3. 建議新增 CAA 紀錄（兩筆）：`@`、Flag 0、Tag issue，值分別是 `letsencrypt.org`（GitHub Pages 使用）與 `pki.goog`（Firebase Hosting 使用）。只允許這兩家憑證機構為本網域發憑證；少了 `pki.goog` 會讓 Firebase Hosting 無法發憑證。
4. 建議在 GitHub 個人設定驗證網域（新增一筆 `_github-pages-challenge-帳號` TXT 紀錄），防止別人冒用你的網域。

## reCAPTCHA v3 沒有「我不是機器人」勾選框是正常的

## 發布失敗怎麼辦（v10 起會自動找原因）

按「檢查並發布」沒有成功時，後台會自動跳出「發布沒有成功：原因與解決步驟」視窗，逐項檢查 8 個設定並用白話說明要修正哪一步。也可以隨時按工具列的「連線診斷」自行檢查（只讀取資料，不會改動網站內容）。

| 視窗顯示的原因 | 怎麼修 |
| --- | --- |
| 還不能發布：有 N 個地方需要修正 | 按每一行的「前往修改」，改好再發布（例如消息沒有標題、軸度不是 0–180） |
| 資料庫規則不是最新版／「網站內容」的部分不是最新版 | 到 GitHub 打開 `firestore.rules` → Copy raw file → Firebase → Firestore → 規則 → 全選貼上 → 發布（專案 ID 要與視窗顯示的一樣） |
| 這個帳號不在管理員名單內 | Firestore → admins → 新增文件，文件 ID 貼上視窗顯示的 UID |
| 連不上資料庫 | 確認網路；對 myopiacare.site 關閉廣告阻擋／內容阻擋器；換網路或瀏覽器 |
| 規則仍是「測試模式」 | 重新貼上 `firestore.rules` 並發布（測試模式約 30 天後會鎖死，且任何人都能讀取客戶資料） |

Facebook、X、Instagram、App 商店與 LINE 連結少打 `https://`、打成 `http://`，或 LINE 只填 `@ID` 時，發布時會自動補成完整網址。仍無法解決時，按視窗的「複製診斷結果」，把文字貼給技術人員。

## 部署（摘要，完整步驟見部署指南文件）

1. GitHub 建立公開 repository → 上傳本資料夾「裡面」的所有檔案。
2. Settings → Pages → Deploy from a branch → `main` / `(root)`；Custom domain 填 `myopiacare.site`。
3. Firebase 建立專案與網頁應用程式 → 設定值貼到 `assets/js/config.js`。
4. Firestore（位置 `asia-east1`）→ 規則分頁貼上 `firestore.rules` → 發布。
5. Authentication 啟用「電子郵件/密碼」→ 新增管理員 → 把 UID 加到 Firestore 的 `admins` 集合。
6. 網域 DNS：4 筆 A、4 筆 AAAA 指向 GitHub Pages，`www` CNAME 指向 `你的帳號.github.io`；生效後勾選 Enforce HTTPS。
7. Authentication → 設定 → 已授權網域加入 `myopiacare.site`。
